## 0. 结论先行

**G1 判定：通过（PASS）。** 买方主导的应付账款融资（反向保理）是成熟、文档充分的业务；角色、合同和资金流都能用公开资料解释清楚；EFSP 设计中的核心环节都有现实对应。原平台经验及五个回忆问题已撤销，不再作为通过条件；欧洲实务约束见第 9 节，产品责任与接口假设转入 G2。

研究带来了 10 条对现有设计的修正或细化，最重要的 5 条：

1. **典型 Payables Finance 模型采用两份双边协议。** 买方与资金方（或付款代理）签服务协议，供应商与资金方签应收账款购买协议，买方不参与后者。→ 领域模型要按"协议关系"建模，而不是一个三方的"融资合同"。
2. **"已批准"不等于"可融资"。** 真实产品在批准之后还有资格条件：供应商是否被指定、期限上下限、发票是否过期（陈旧期）、是否已融资或已付款。
3. **资金方有权拒绝任何一笔，但产品普遍支持自动直通处理。** 两者并存，资金方"逐笔审批"和"规则内自动购买"都是真实模式。
4. **EFSP 选择不持有客户资金的第三方编排平台定位。** C2FO 明确说明不代买方付款，Taulia 在其 XTF 产品说明中明确不持有资金。付款由资金方和买方的银行执行，平台负责撮合、指令、记录和报告。EFSP 的"放款"应建模为"向资金方发出购买与付款请求，并跟踪确认"。
5. **到期回款可通过“收款人变更”实现。** 发票被提前支付后，买方应付系统里的收款人改为资金方，买方照常在付款批次中付款，钱就到了资金方。这是特定产品路径，付款代理等其他安排也存在；G2 明确 EFSP 采用的结算路径。

## 2. 参与方、协议与责任

| 角色 | 签什么协议 | 做什么 | 承担什么风险 | 来源 |
|---|---|---|---|---|
| 买方（锚定方） | 与付款代理或资金方签服务协议（PSA） | 发起项目、选择付款代理、指定合格供应商、分别记录发票内部批准与协议下的正式付款承诺、到期全额付款 | 承担到期付款义务；适用相关会计准则时承担披露责任 | BAFT、GSCFF、Taulia |
| 供应商 | 与资金方签应收账款购买协议（RPA） | 自愿参加；自己选择哪些发票提前收款；保证应收账款没有被质押或转让给他人 | 无追索模型下买方信用风险转移；欺诈、虚假陈述及协议例外仍可能追索 | BAFT、GSCFF |
| 资金方 | 与供应商签 RPA；与买方或付款代理签服务协议 | 买下应收账款并提前付款；可拒绝任何一笔；到期收取全额 | 买方信用风险（定价依据） | BAFT、GSCFF |
| 付款代理 / 平台 | 由买方选定 | 运营项目；可以就是资金方（银行自建平台），也可以是第三方平台（如 Orbian、PrimeRevenue 等多银行平台） | 运营风险 | BAFT、IFC |
| 银行（支付执行） | 各方自己的开户行 | 执行转账、提供状态回执和对账单 | — | ISO 20022 |

**适用范围**：BAFT 所述典型双边模型中，买方不是 RPA 的一方，供应商不是 PSA 的一方；不能据此断言所有业务均禁止三方协议。

## 3. 端到端生命周期：从项目建立到结清

### A. 项目建立

| # | 发生什么 | 标签 | 来源 | 对 EFSP 的含义 |
|---|---|---|---|---|
| A1 | 买方选择付款代理/资金方，签服务协议，建立项目 | 【事实】 | BAFT、GSCFF | 需要 `Program`（买方 × 资金方） |
| A2 | 以买方信用作为融资的经济基础 | 【事实】 | GSCFF（Anchor 定义） | 额度围绕买方敞口设置 |
| A3 | 设置项目参数：最短/最长期限、最低/最高融资比例、陈旧期、宽限期、是否有追索、节假日顺延规则、是否自动接受、是否自动发起融资 | 【产品】 | Oracle | 资格规则和日期计算来自项目参数 |
| A4 | 买方指定哪些供应商可以参加 | 【产品】 | Taulia | 需要"供应商入驻/资格"记录 |
| A5 | 供应商受邀、激活账户、签 RPA、完成 KYC | 【事实】 | GSCFF、SAP | V1 预置已入驻供应商【假设】 |

### B. 发票进入平台

| # | 发生什么 | 标签 | 来源 | 对 EFSP 的含义 |
|---|---|---|---|---|
| B1 | 买方 ERP 同步已批准的应付发票到平台；供应商不需要自己上传 | 【产品】 | Taulia、C2FO | 发票的权威来源是买方；需要批量导入的幂等 |
| B2 | 只有买方完成匹配、且没有未决争议的发票才会进入 | 【产品】 | C2FO | 争议在进入之前解决 |
| B3 | 协议下的正式付款承诺须与 ERP 内部批准区分 | 【事实】（限定模型） | BAFT、GSCFF；前次 G1 审查 | 记录承诺内容、版本和证据；内部批准本身不自动等于不可撤销承诺 |
| B4 | 商业争议（贷项通知、抵销、质保）在项目之外处理 | 【事实】 | BAFT | V1 不做贷项通知有依据 |
| B5 | 买方在规定天数内未明确接受，视为接受 | 【产品】 | Oracle | 可选，V1 不做 |

### C. 资格与报价

| # | 发生什么 | 标签 | 来源 | 对 EFSP 的含义 |
|---|---|---|---|---|
| C1 | 只有"已接受/部分融资"且"未付/部分付款"的发票可申请；已全额融资的不再列出 | 【产品】 | Oracle 企业端手册 | **资格判断独立于批准**，是一个单独的业务判断 |
| C2 | 超过陈旧期的发票不会被自动融资 | 【产品】 | Oracle | 资格规则之一 |
| C3 | 融资成本与买方信用挂钩 | 【事实】 | GSCFF、BAFT | 定价输入是买方，不是供应商 |
| C4 | 只按融资天数收费，费用在提前付款时扣除 | 【产品】 | SAP 供应商说明 | 贴息预扣；付款额 = 面值 − 贴息 |

| C6 | 可选的提前付款日期取决于资金来源和付款方式；还款日必须是资金方接受还款的日期 | 【产品】 | Taulia | 需要营业日历 |

## 4. 对 EFSP 设计的修正与细化

| # | 研究发现 | 对 EFSP 的影响 | 处理 |
|---|---|---|---|
| R1 | 典型模型采用两份双边协议，非行业唯一合同形式 | 领域模型：`Program`（买方 × 资金方）+ `SupplierEnrollment`（供应商在项目内的入驻） | 采纳 |
| R2 | 批准之后还有资格条件 | 资格判断是独立的业务规则，输入来自项目参数 | 采纳 |
| R3 | 资金方可拒绝任何一笔，也可配置自动购买 | 融资请求包含"资金方决策"一步；V1 规则内自动接受 | 采纳 |
| R4 | EFSP 选择不经手资金的产品边界 | "放款"= 向资金方发出付款请求并跟踪确认；平台账本记录的是项目内各方之间的应收应付和预期资金变动，而不是任何一方的正式会计账 | 采纳方向；账本视角在 G2 定稿 |
| R5 | 收款人变更为资金方 | 新增业务事件"收款人变更"，需要通知买方 ERP；到期对账依赖它 | 采纳 |
| R6 | 超额度处理是可配置策略（Oracle 可停止、跳过或照常占用；Taulia 动态折扣按流动性上限拒绝） | V1 硬拒绝是产品选择，不是行业规则 | 采纳，在文档中如实标注 |
| R7 | 节假日调整放款日和到期日 | 需要营业日历 | 采纳；V1 普通 SCT 日历包含周末与 TARGET 关闭日，另明确 PSP 截止时间等假设（第 9 节） |
| R8 | 对账有"部分"和"未对账"状态；多付、少付有配置化处理 | 对账结果不只是"成功/失败" | 采纳 |
| R9 | 每日批处理普遍存在（每日撮合、日终批量、预付资金报告） | 定时任务和截止时间是真实需求 | 采纳；V1 至少一个每日到期任务 |
| R10 | 平台给出的申请参考号；状态回执带原始标识 | 幂等和对账都有真实的标识依据 | 采纳 |

## 5. G1 问题清单

### 5.1 已回答

| 问题 | 答案 | 来源 |
|---|---|---|
| 谁发起项目？ | 买方 | GSCFF、BAFT、IFC |
| 谁能申请提前收款？ | 买方指定的合格供应商，自愿参加 | Taulia、BAFT |
| 什么发票能融资？ | 已批准、无未决争议、未融资未付款、在期限和陈旧期之内 | BAFT、C2FO、Oracle |
| 谁出钱？ | 资金方；动态折扣时是买方自己 | GSCFF、C2FO |
| 资金方逐笔审批还是自动？ | 两者都存在：资金方有权拒绝任一笔，产品也支持自动直通 | BAFT、Oracle |
| 融资后发票出现争议怎么办？ | 按所采用协议在融资前解决争议；正式付款承诺与普通内部批准区分，商业争议在项目外处理 | BAFT |
| 到期时钱怎么回到资金方？ | 收款人改为资金方，或由付款代理代买方付款 | Taulia、BAFT |
| 平台是否经手资金？ | EFSP 不持有客户资金；这是所选产品边界 | C2FO、Taulia |
| 额度超了怎么办？ | 拒绝（Taulia 动态折扣的流动性上限），或按配置停止、跳过、照常占用（Oracle） | Taulia、Oracle |

| 平台与资金方接口如何定义？ | V1 使用 API + 异步回执【假设】，语义参考 ISO 20022；不宣称存在统一平台接口 | G2 |
| 付款超时、重复回执如何恢复？ | 外部支付接口契约与故障验证；不以原平台经历或未证实频率作依据 | G3/G4 |
| 额度按面值占用还是按资金方实付占用？ | 无统一规则，属于项目政策 | G2（V1 按面值【假设】） |
| 平台账本站在谁的视角？贴息差额怎么记？ | 设计决策 | G2 |
| 买方逾期时，平台承担什么职责：只提醒，还是参与催收？ | 设计决策 | G2 |

---

## 6. 证据边界与已撤销事项

原平台经验不再作为设计依据，原分流问题和五个回忆问题均已撤销。G1 依据欧洲实际业务、行业定义、产品文档和支付规范完成；不再要求用户补充从业记忆。

特定产品行为不得自动上升为行业规则；公开资料不能确定的接口、额度口径和账本视角明确标为假设，交由 G2 决策。历史原稿保存在 references 中，仅供追溯。

## 7. V1 合理简化清单（每条都有依据或明确标为假设）

| 简化 | 性质 | 依据 |
|---|---|---|
| 单买方项目、单资金方 | 【假设】 | 真实项目可有多个资金方（IFC 提到多银行平台） |
| 不做供应商 KYC 和入驻流程，预置已入驻供应商 | 【假设】 | KYC 真实存在（GSCFF），但不产生 V1 要验证的工程问题 |
| 不做争议和贷项通知 | 有依据 | BAFT：商业争议在项目外处理 |
| 融资额 = 面值 − 贴息 | 有依据 | GSCFF：通常约 100% 面值减贴息 |
| 贴息预扣、按融资天数计 | 有依据 | SAP 供应商说明 |
| 超额度硬拒绝 | 【产品】选择 | Taulia 动态折扣同样拒绝；Oracle 可配置 |
| 资金方规则内自动接受 | 【产品】选择 | Oracle 自动发起融资 |

| 按发票对账 | 【产品】选择 | Oracle 可按发票或按融资 |

## 9. 欧洲实务约束（承接前次补充与审查）

### 9.1 V1 场景假设

【假设】运营地荷兰、合同选择荷兰法、EUR + 普通 SEPA Credit Transfer（SCT），暂不引入 SCT Instant。60 天账期演示中的供应商设为非 SME。跨境债权转让不能仅凭合同选法就推定全部法律问题均适用荷兰法。

### 9.2 支付、转让与披露边界

| 约束 | 继承的研究结论与适用范围 | 对 EFSP 的影响 |
|---|---|---|
| 重复付款与 Recall | 重复发送或技术错误相关 Recall 的发起期限为原交易执行后 10 个银行营业日；收款 PSP 收到后 15 个银行营业日内回应。欺诈另有期限，Recall 不保证追回；规则直接约束参与 PSP。[E1] | 同一业务保持稳定操作标识，分别处理内部防重与资金方防重；超时保持结果未知，先查询与核对，不凭超时生成新付款 |
| Verification of Payee | 前次研究确认欧元区相关 PSP 自 2025-10-09 起适用普通及即时欧元转账的核验要求；不匹配不等于法规强制拒付，非消费者批量付款存在退出安排。[E2] | Match、Close Match、No Match、Unable to Verify 等结果需要记录；暂停异常请求并人工审核属于 EFSP 产品策略，处理权限由 G2 定稿 |
| 在途、拒绝与退回 | 普通 SCT 存在受受理时间、截止时间及银行营业日影响的执行周期；“最长一个营业日”不能直接套用为从平台点击到供应商到账的统一 SLA。拒绝、结算后退回与 Recall 是不同流程。[E1] | 分开记录指令创建、外部受理、执行/结算证据、拒绝及退回；ACCEPTED 本身不能证明供应商最终入账 |
| 银行营业日历 | 前次研究记录 2026 TARGET 关闭日为 01-01、04-03、04-06、05-01、12-25、12-26；周末另计。普通 SCT 的 PSP 受理规则与截止时间也需要建模，不能外推到全天候即时支付。[E3] | 撤销“只处理周末”；日期调整规则作为项目参数，在 G2 明确 |
| 荷兰应收账款转让 | 前次研究引用 2025-07-01 生效的 Wet opheffing verpandingsverboden，针对适用范围内的债权转让记录书面通知要求；具体效力须区分适用债权及交易安排。[E4] | 购买协议、转让事实、通知发送/送达证据及付款对象更新分别追踪；买方确认收悉可作运营证据，不默认是统一法律生效条件 |
| 付款期限 | 荷兰大型企业向符合条件的 SME 付款适用最长 30 天；一般 B2B 通常 60 天，存在适用条件及例外，不能仅按企业国籍判断。[E5] | 60 天演示使用非 SME 供应商；账期与适用法作为明确场景假设 |
| 供应商融资披露 | IAS 7 / IFRS 7 的披露修订针对适用相关会计准则的企业，不是所有买方一律适用。[E6] | 提供项目级披露支持数据；买方承担最终会计判断、财报编制及披露责任 |
| 资金方接口 | 公开材料未确定适用于 EFSP 的唯一接口形式 | 【假设】API + 异步回执，语义参照 ISO 20022；不宣称模拟接口是银行标准或完整报文实现 |
